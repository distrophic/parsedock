Чек-лист ParseDock
===================

Файл для ручной сверки. Идите по пунктам и отмечайте [x], когда проверили сами.
Обычные тесты не ходят на внешние сайты.
Проверки окна шли без настоящего щелчка мышью по живому окну: режим без дисплея.
Живой щелчок по окну на экране отмечайте отдельно, когда пройдёте его сами.

Когда сверять целиком
---------------------
Полный проход — после оставшихся функций из PROJECT_SPEC.md.
Пока их нет, пункты раздела «Ещё не сделано» не отмечайте как готовые.


Ещё не сделано
--------------
[ ] Клиент playwright разрешает имя внутри Chromium. У requests и curl_cffi
    соединение идёт на уже проверенные адреса. Публикацию не делать, пока вы не попросите.
[ ] Лицензия MIT в файле LICENSE. Публикацию не делать, пока вы не попросите.


Подготовка к GitHub
-------------------
Файлы README.md, CONTRIBUTING.md, SECURITY.md, CHANGELOG.md, LICENSE.
Репозиторий не публиковался.
[ ] В README перечислены только уже сделанные возможности.
[ ] Ограничения, терминал и запуск кода на месте.
[ ] Команды установки для Linux и Windows разделены.
[ ] Первый пример — локальный examples/cards/profile.json.
[ ] Сценарий CI в описании не назван уже выполненным на GitHub.

Запрос
------
[ ] Только GET.
[ ] Таймаут на соединение и на чтение.
[ ] Ограничение размера ответа.
[ ] Редиректы вручную, у каждого перехода проверяется адрес.
[ ] Проверка адреса: служебные и ссылочно-локальные адреса закрыты.
    Частные сети открываются только явной галочкой доверия.
[ ] Вкладка Requests всегда ходит через библиотеку requests.
[ ] Вкладка curl_cffi отдельно. Это отпечаток клиента, не браузер и не обход блокировки.
[ ] Имя tor145 — имя отпечатка, не сеть Tor.
[ ] При сбое requests браузер сам не открывается.


Профиль
-------
[ ] Схема версии 1. Новые поля не ломают старые профили.
[ ] Неизвестное поле в JSON — ошибка.
[ ] Пути в профиле считаются от папки этого файла.
[ ] Профиль — локальный доверенный файл. Песочницы путей нет.
[ ] Секреты в профиль не записываются.


XML
---
Своё правило, не CSS. Пример: examples/cards/catalog.xml и profile-xml.json.
[ ] Путь записи, например catalog/item. Первый шаг — корень, дальше прямые потомки.
[ ] Поле внутри записи своим путём. «.» — сам элемент записи.
[ ] Пустой элемент и отсутствующий элемент различаются.
[ ] Цена вне записи не попадает в карточку (999 в catalog.xml).
[ ] DTD и сущности в файле отклоняются.
[ ] Вкладка XML открывает сохранённый файл и показывает записи.

HTML
----
[ ] Контейнер и поля внутри карточки, а не по всей странице.
[ ] Пустая строка, отсутствие значения, ноль и ошибка преобразования — разные случаи.
[ ] Цена вне карточек в пример не попадает (999 на странице examples/cards/page.html).
[ ] Предпросмотр: одна страница, файл не пишется, обход и robots.txt не запускаются.


Обход
-----
[ ] По умолчанию одна страница, robots.txt не запрашивается.
[ ] Режим параметра страницы.
[ ] Режим ссылки «следующая».
[ ] Лимит страниц.
[ ] Галочка robots.txt. Это не юридическое разрешение.
[ ] Если robots.txt недоступен и стоит режим ошибки или запрета — страницы не качаются.


Повторы
-------
[ ] По умолчанию одна попытка. Старый профиль сам не повторяет запрос.
[ ] Число попыток, минимальная пауза, рост паузы.
[ ] Повторяются таймаут, обрыв соединения и коды 408, 429, 500, 502, 503, 504.
[ ] Отказ политики адресов не повторяется.
[ ] Запросы идут по очереди, не параллельно.


Данные
------
[ ] Лишние пробелы.
[ ] Число.
[ ] Валюта.
[ ] Дата.
[ ] Относительный адрес становится абсолютным.
[ ] Можно оставить исходное значение рядом.
[ ] Ключи без дублей: остаётся первая запись.
[ ] Пустой ключ, отсутствие значения и пустой список между собой не склеиваются.


Файлы
-----
[ ] JSONL: UTF-8, перевод строки \n.
[ ] CSV: кодировка, один символ-разделитель, перевод строки \r\n.
    Пустое значение и отсутствие значения в ячейке выглядят одинаково пустыми.
    Строка, похожая на формулу, помечается как текст.
[ ] SQLite: локальный файл, не сервер. Таблица records.
    NULL и пустая строка различаются. Число остаётся числом.
[ ] Режим «создать» не затирает уже существующий файл.
[ ] Кнопка «Сохранить SQLite» на вкладке JSON.
[ ] Галочка замены файла действует и на базу.


Задание
-------
[ ] Отмена.
[ ] Итог: состояние, счётчики, путь, причина остановки на английском токене.
    finished — успешное завершение.
[ ] Продолжение с файла (например state.json) только вместе с обходом нескольких страниц.
[ ] Пустое поле продолжения начинает обход сначала.
[ ] Это не гарантия «ровно один раз»: если процесс умрёт между записью результата
    и записью state.json, страница может попасть в файл дважды.
[ ] Чужой state.json к другому профилю не применяется и файл результата не меняет.


Браузер
-------
[ ] Playwright только если в профиле явно указан client: playwright.
[ ] Окно само браузер не открывает.
[ ] Это headless Chromium, не обход капчи и не ваш профиль Chrome.
[ ] Пакет в обычный набор не входит. Без него requests не подставляется молча.


Окно
----
[ ] Вкладки: Requests, curl_cffi, HTML, JSON, CSV, XML, Code, Terminal.
[ ] То, что ещё не подключено, так и написано на вкладке, без имитации работы.
[ ] Запуск: python -m parsedock.desktop
    Linux: .venv/bin/python -m parsedock.desktop
    Windows: .venv\Scripts\python -m parsedock.desktop


Терминал
--------
Это запуск одной введённой команды, не эмулятор терминала.
Команда python -m parsedock профиль.json по-прежнему отдельно.
[ ] Команду вводите вы. Из адреса страницы она не собирается.
[ ] Это сессия на всю систему, не выбор одной папки проекта.
    Старт из домашней папки. cd сохраняется для следующей команды.
[ ] Оболочка: на Windows cmd или PowerShell, на Linux sh или bash.
[ ] Обычный вывод и ошибки видны в одной панели.
[ ] Кнопка «Остановить» завершает сессию.
[ ] Удалённого доступа и отдельного порта нет.
[ ] Окно при этом не замирает.
[ ] Полноэкранные программы вроде vim эта панель не ведёт.

Код
---
Скрипт собирается из вкладок Requests и HTML. Модель по сети не вызывается.
[ ] Кнопка «Собрать» только показывает код.
[ ] «Сохранить» спрашивает подтверждение. Существующий файл заменяется только после второго вопроса.
[ ] «Запустить» спрашивает отдельно и выполняет только сохранённый файл.
[ ] Строка о синтаксисе прямо говорит, что это не проверка безопасности.
[ ] Заголовки запроса, включая токен, в скрипт не копируются.


Linux и Windows
----------------
Файл .github/workflows/tests.yml. Обычный запуск: Ubuntu и Windows, Python 3.10 и 3.12.
Живой браузер этим файлом не ставится. Пока репозиторий не отправлен на GitHub, этот сценарий там не выполнялся.
[ ] На Ubuntu тесты проходят без внешнего сайта.
[ ] На Windows тесты проходят без внешнего сайта.
[ ] Окно в CI запускается без дисплея.
[ ] Тесты с пометкой browser в обычный запуск не входят.

Безопасность
------------
Часть уже есть в ядре. Полный проход — отдельный пункт «ещё не сделано».
[ ] TLS-проверка включена. Ради удобства её не выключают.
[ ] eval и exec нет.
[ ] Секреты не в примерах и не в обычном журнале.
[ ] Адреса проверяются до соединения и на каждом редиректе.
[ ] Authorization, Cookie и Proxy-Authorization не уходят на другой хост или порт при редиректе.
    На том же адресе они сохраняются.
[ ] Если файл результата, профиль или скрипт — символическая ссылка, запись не начинается и цель ссылки не меняется.
[ ] requests и curl_cffi соединяются с уже проверенными адресами, даже если имя больше не разрешается.
[ ] У клиента playwright имя по-прежнему разрешает Chromium.
