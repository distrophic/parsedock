# ParseDock

Локальная программа на Python: читает сохранённую страницу или один HTTP GET и записывает строки в JSONL, CSV или SQLite. Есть окно на PySide6 и запуск одного профиля из командной строки.

Имя ParseDock рабочее. Свободно ли оно на GitHub, PyPI и как товарный знак, отдельно не проверялось. Пакет на PyPI не публиковался.

Лицензия MIT, текст в файле `LICENSE`. Правообладатель в этом файле: AlexLess, 2026.

## Что уже есть

- Разбор HTML: контейнер CSS и поля относительно него.
- Разбор XML: путь из имён элементов, без CSS и без XPath.
- Запись JSONL, CSV и SQLite. Режимы `create`, `replace`, `append`.
- Профиль JSON схемы версии 1. Неизвестный ключ — ошибка.
- Один GET через библиотеку `requests`. Проверка TLS включена. Повторы сами не включаются.
- Обход страниц: список адресов, ссылка «далее», параметр номера страницы. `robots.txt` читается только если это включено в профиле.
- Преобразования по имени: пробелы, число, валюта, дата, абсолютный адрес. Произвольный Python в профиле не выполняется.
- Удаление дублей по ключам. Первая строка остаётся.
- Предпросмотр одной страницы без записи файла.
- Повторы с ограничением попыток, паузой и ростом паузы. Запросы идут по очереди.
- Продолжение обхода по файлу состояния. Это не гарантия «ровно один раз».
- Дополнительно: `curl_cffi` и Playwright. Окно Playwright не открывает.
- Окно: запрос, ответ, HTML, XML, сохранение, код, локальная оболочка.
- Генератор скрипта из профиля. Заголовки запроса в скрипт не копируются.
- Командная строка: `python -m parsedock profile.json`.

Вкладка JSON показывает записи последней страницы. Отдельного извлечения из JSON-документа нет.

## Ограничения

- Только GET. Тело POST в окне не отправляется.
- Обычные тесты не ходят на внешние сайты.
- Профиль — доверенный локальный файл. Отдельной песочницы для путей нет.
- Служебные и ссылочно-локальные адреса закрыты. Частные сети открываются только `trust_private_networks`.
- `requests` и `curl_cffi` соединяются с адресами, которые уже прошли проверку. Клиент `playwright` отдаёт разрешение имени самому Chromium, и там зазор остаётся.
- Секретные заголовки `Authorization`, `Proxy-Authorization` и `Cookie` не уходят на другой источник при редиректе. На том же источнике остаются.
- Запись результата через символическую ссылку отклоняется. На этой Windows создание ссылки в тесте не удалось, поэтому этот случай здесь не выполнялся.
- `curl_cffi` с `impersonate` подставляет отпечаток клиента. Это не браузер и не обход блокировки. Имя `tor145` — отпечаток, не сеть Tor.
- Playwright — отдельный headless Chromium, только если в профиле `client` равен `playwright`. Капчу он не обходит. Профиль Chrome пользователя не читается.
- `robots.txt` не является юридическим разрешением.
- Терминал в окне — сеанс оболочки с правами текущего пользователя. Команды из адреса, HTML, профиля и сгенерированного кода сами не запускаются.
- Кнопка «Запустить» на вкладке Code выполняет сохранённый файл скрипта этим интерпретатором Python.

## Платформы

Проверено локально: Windows, Python 3.12.10. Требование пакета: Python 3.10 и новее.

Файл `.github/workflows/tests.yml` рассчитан на Ubuntu и Windows, Python 3.10 и 3.12. На GitHub этот сценарий ещё не выполнялся, поэтому поддержка Ubuntu этим файлом не подтверждена.

Fedora 44 — предполагаемая основная система. В этой сессии установка на Fedora не запускалась. Команды ниже для Linux те же, что для другого дистрибутива с Python 3.10+.

Колёса PySide6 и `curl_cffi` зависят от версии Python и системы. Если установка дополнения падает, смотрите текст pip: это не доказательство, что само ядро без этого дополнения сломано.

## Установка

Из каталога проекта.

Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -e ".[dev]"
```

Windows (PowerShell):

```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -U pip
.venv\Scripts\python -m pip install -e ".[dev]"
```

Дополнения ставятся так же, списком в кавычках:

| Дополнение | Зачем |
| --- | --- |
| `dev` | pytest |
| `desktop` | окно PySide6 |
| `curl` | клиент `curl_cffi` |
| `browser` | пакет Playwright |

Пример окна и curl сразу:

```powershell
.venv\Scripts\python -m pip install -e ".[desktop,curl]"
```

После `browser` браузер ещё нужно скачать отдельно: `python -m playwright install chromium`. Обычные тесты этого не требуют.

## Первый запуск

Локальный пример, без сети. Профиль `examples/cards/profile.json` читает `page.html` и пишет `cards.jsonl` рядом. Режим `create` откажется, если файл уже есть: уберите его или смените режим в профиле.

Linux:

```bash
.venv/bin/python -m parsedock examples/cards/profile.json
```

Windows:

```powershell
.venv\Scripts\python -m parsedock examples/cards/profile.json
```

Ожидается состояние «Задание завершено» и три записи: чайник, кружка, ложка. Цена 999 вне карточек в файл не попадает.

XML-пример: `examples/cards/profile-xml.json` и `catalog.xml`.

Окно:

```powershell
.venv\Scripts\python -m parsedock.desktop
```

На Linux путь к интерпретатору — `.venv/bin/python`. Если PySide6 не установлен, программа завершается с сообщением, без подмены на другой интерфейс.

Тесты, без внешних сайтов:

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.venv\Scripts\python -m pytest --basetemp=D:\ParserDock\.pytest-tmp
```

На Linux временный каталог можно не задавать. На Windows каталог pytest внутри профиля пользователя иногда даёт отказ в доступе, поэтому здесь указан каталог внутри проекта. `.pytest-tmp` в git не входит.

## Примеры профилей

Все лежат в `examples/cards/`.

| Файл | Что показывает |
| --- | --- |
| `profile.json` | локальный HTML, JSONL |
| `profile-csv.json` | CSV |

## Терминал и запуск кода

Вкладка Terminal открывает `cmd` или PowerShell на Windows и `sh` или `bash` на Linux. Сеанс начинается в домашнем каталоге. `cd` сохраняется. Это не полный эмулятор терминала: полноэкранные программы вроде редактора не рассчитаны.

Вкладка Code собирает скрипт из вкладок Requests и HTML. Сохранение спрашивает подтверждение. Запуск идёт только для уже сохранённого текста, отдельным процессом, без оболочки командной строки. Скрипт делает то, что разрешает профиль, включая запись файла и HTTP GET.
